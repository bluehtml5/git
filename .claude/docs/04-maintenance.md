# 維護協議：怎麼安全地更新這套制度檔

> 適用對象：未來所有 session 的模型。制度檔會過時，該更新就更新——但按這份協議來，避免把制度改壞。

## 權限分級：什麼可以自己改、什麼要先問使用者

**可自行修改（不用問）**：
- 附加教訓到 `lessons.md`（見下方格式）。
- 修正**查證過**的事實錯誤：路徑不存在、工具改名、模型枚舉變了。判準：你能貼出證據（命令輸出、官方文件連結）。改的時候在該行後加 `<!-- 更新於 YYYY-MM-DD，依據：… -->`。
- 為既有規則補充範例（不改規則本身）。
- 錯字、格式。

**必須先問使用者（用 AskUserQuestion，附「現行規則／建議改法／理由」）**：
- 刪除或放寬任何規則（重試上限、驗證不自驗、隨做隨 push……）。特別警告：**「這條規則很煩」不是放寬的理由——這些規則就是設計來擋住模型的自然傾向的**。
- 改變 CLAUDE.md 的結構或新增硬規則。
- 新增/刪除 `.claude/agents/` 底下的 agent 定義。
- 任何你「覺得應該改但說不出具體證據」的修改。

**絕對禁止**：因為規則擋住了你當下想做的事而修改規則。先照規則做完，事後再提修改建議。

## 修改前的備份規則

這是 git repo，**commit 就是備份**：改制度檔前先確認工作樹乾淨（`git status`），單獨一個 commit 只改制度檔，訊息寫明「改了哪條＋為什麼」。這樣任何一版都能 `git log -- <檔案>` 找回。大幅重寫（超過半個檔案）時，額外把舊版存到 `.claude/docs/archive/<檔名>.<YYYYMMDD>.md` 再動手。

## 教訓寫回：lessons.md

**什麼值得寫**：花了你超過 3 次來回才發現的事實、制度檔沒涵蓋而你踩到的坑、使用者糾正你的偏好。**不值得寫**：一次性的任務細節、已在制度檔裡的規則重述。

**格式（每條 4 行，嚴格遵守）**：

```
## YYYY-MM-DD 一句話標題
- 情境：當時在做什麼
- 坑：具體錯在哪（附錯誤訊息關鍵行或 檔案:行號）
- 規則：一行可執行的「下次遇到 X 就 Y」
```

寫完 commit + push（訊息開頭用 `lessons:`）。

## 精簡協議（防止制度膨脹成沒人讀的長文）

- **觸發條件**：`lessons.md` 超過 25 條，或任何制度檔超過 150 行。
- **動作**：派一個 `opus` subagent 做歸併：重複的教訓合併、已寫進制度檔的刪除、真正通用的教訓「晉升」進對應制度檔（晉升要走上面的權限分級——動規則就要問使用者）。
- **歸併時必查**：新舊條目有沒有互相矛盾。有矛盾不要自行裁決，列給使用者選。
- 精簡前把舊版存 `archive/`。

## 制度健康檢查（每次被要求「整理」或每 10 個 session 左右做一次）

1. CLAUDE.md 路由表指向的每個檔案都存在（Glob 驗證）。
2. 制度檔引用的工具名、模型名、agent 名在當前環境仍有效（環境會演化，枚舉會變）。
3. 隨機抽一個模板實際派工跑一次，確認弱模型照著做能成功。
發現失效就按權限分級處理：事實類自修，規則類問使用者。
