# 派工 prompt 模板

> 用法：複製對應模板，填掉所有 `【】` 空格後派工。**空格填不出來 = 你還沒想清楚任務，先想清楚再派。**
> 每個模板已內建三件套（目標與動機／驗收條件／回報格式）與回報合約。model 選擇依 `01-delegation.md` 第 3 節選型表。

## 1. 搜尋（subagent_type: Explore，model: sonnet；純機械查找可 haiku）

```
目標：找出【要找什麼，愈具體愈好】。
動機：我接下來要【拿結果做什麼】，所以我需要知道【哪些面向：位置/呼叫關係/資料流】。
範圍：從【起點目錄或檔案】開始；已知線索：【關鍵字/檔名/函式名，沒有就寫「無」】。
驗收條件：
- 每個結果附 檔案:行號 ＋ 一行說明它為什麼相關。
- 找不到也要回報：搜過哪些關鍵字與目錄，讓我能判斷是真的沒有還是沒搜到。
回報格式：結果清單（最多【N，建議 20】筆，超過只回總數＋最相關前 N 筆）。不要貼檔案內容全文。
```

## 2. 實作（subagent_type: general-purpose，model: sonnet；牽涉架構決策用 opus）

```
目標：實作【功能，一句話】。
動機：【為什麼要做、誰會用到】。邊界情況照這個動機自行判斷，拿不準的列出來回報而不是亂猜。
規格：
- 輸入/輸出：【】
- 要動的檔案（已知的話）：【檔案:行號】
- 不要動的範圍：【明確排除，例如「不要改既有測試」「不要動 public API」】
- 風格：跟隨周邊既有程式碼的慣例，不引入新依賴（需要新依賴時先回報，不要直接裝）。
驗收條件：
- 【具體可驗行為，例：呼叫 X(a,b) 回傳 c；輸入非法值時拋 YError】
- 跑【測試命令】全綠；新行為有至少一個新測試。
完成後：commit（訊息說明「做了什麼＋為什麼」）並 push 到【分支】。
回報格式：改了哪些檔案（檔案:行號）、測試輸出關鍵行、自行做的判斷清單（含理由）。不要貼整個 diff。
```

## 3. 重構（subagent_type: general-purpose，model: sonnet）

```
目標：把【範圍】從【現狀】重構為【目標型態】。
動機：【為什麼值得動，例：重複邏輯已出現在 N 處】。
鐵律：重構 = 行為不變。任何觀察得到的行為改變都算失敗，包括錯誤訊息文字。
步驟要求：
1. 動手前先跑【測試命令】記下基準結果（幾個通過/失敗）。基準本來就有失敗的測試，記下清單，重構後允許它們同樣失敗，但不允許新增失敗。
2. 小步改、每完成一個獨立步驟 commit 一次。
3. 結束後重跑同一命令，對照基準。
驗收條件：測試結果與基準一致；【要消除的重複/壞味道】已不存在（用 grep 證明，附命令與輸出）。
回報格式：基準 vs 結束的測試對照、每個 commit 一行說明、grep 證明。不要貼整個 diff。
```

## 4. 研究（subagent_type: general-purpose，model: sonnet；結論會影響重大決策用 opus）

```
目標：回答【具體問題，可判定「答完了沒」的形式】。
動機：這個答案會決定【後續什麼決策】，所以請特別關注【決策相關的面向】。
資料來源優先序：【官方文件 > repo 內事實 > 其他網頁】。今天日期是【日期】，注意資料時效。
驗收條件：
- 每個關鍵結論附來源（URL 或 檔案:行號）。
- 區分「查證過的事實」與「你的推論」，分開標示。
- 查不到的就寫「查不到」，禁止編造。互相矛盾的來源要並列並說明你採信哪個、為什麼。
回報格式：先一段直接回答問題，再列證據。全文超過 40 行就寫到【scratchpad 或 .claude/docs/ 下的檔案路徑】，只回摘要＋路徑。
```

## 5. 審查／驗收（subagent_type: verifier，model: 定義檔已設 sonnet/high；高風險改 opus）

```
請驗收以下產出。你沒有參與製作，請只相信你親眼驗證到的。
產出位置：【檔案路徑們，或「branch X 上最近 N 個 commit」】。
背景一句話：【這產出是要做什麼的】。
驗收條件（逐條給證據）：
- 【條件 1，可機械檢查】
- 【條件 2】
- 內文引用的所有路徑、工具名、命令都真實存在（自己查證）。
- 【程式碼類加：跑「測試命令」，貼關鍵輸出】
回報格式：第一行 PASS/FAIL；逐條 ✅/❌＋一行證據；FAIL 列出每個問題的 檔案:行號。
```

## 通用附註（所有模板適用）

- 派工後 subagent 回報 FAIL 或內容不合回報合約 → 依 `01-delegation.md` 第 5 節處理（升級或換路），不要默默收下爛回報。
- 多個**互相獨立**的任務可以同一回合平行派；有相依關係的必須等前一個結果。
- subagent 看不到主對話。你以為「它應該知道」的每件事，都要寫進 prompt。
