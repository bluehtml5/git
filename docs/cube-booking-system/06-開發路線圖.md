# 06. 開發路線圖

## 階段規劃

### Phase 0 — 基礎建設（1~2 週）
- Monorepo 建置（前後端 + 共用型別）、CI/CD、環境（dev/staging/prod）
- 認證框架（JWT + RBAC + 多租戶中介層）
- 資料庫 schema migration 機制

### Phase 1 — MVP（核心閉環，約 6~8 週）

> 目標：一家商家能完整跑通「上架項目 → 排班 → 會員預約 → 扣減 → 報到完成」

**商家端**
- 商家設定、預約項目（時長/buffer/扣減方式）
- 服務人員 + 週期班表 + 請假例外
- 行事曆（日/週視圖）、代客預約、報到
- 販售堂數卡、會員列表

**用戶端**
- 手機 OTP / LINE 登入
- 商家頁、項目列表、可預約時段查詢
- 建立預約（扣堂數）、我的預約、取消（含返還）
- LINE 預約成立 + 前一天提醒

**系統**
- 預約狀態機（pending/confirmed/checked_in/completed/cancelled）
- 防超賣（Redis 鎖 + DB 排除約束）
- 帳本式扣減引擎

### Phase 2 — 政策與體驗（4~6 週）
- **遲到流程**：寬限設定、遲到回報、late → no_show 自動化、爽約罰則
- **改期**：自助改期（期限/次數限制）、商家拖曳改期
- 取消政策階梯式返還
- 儲值金、點數（多種扣減方式並存）
- 卡券有效期與到期提醒
- 審核制預約、候補機制
- 通知模板管理、簡訊通道

### Phase 3 — 多商家平台化（4~6 週）
- 平台管理端：商家入駐、方案訂閱、功能開關
- 團體課程（容量、報名、候補轉正）
- 資源型預約（場地/設備）
- 報表：營收、出席率、稼動率、熱力圖
- 金流串接（線上付款、儲值）

### Phase 4 — 成長功能（持續迭代）
- Google Calendar 雙向同步
- 會員等級 / 行銷（優惠券、推薦碼、生日禮）
- 多分店支援
- 開放 API / Webhook 給第三方
- 數據看板進階（RFM 分群、流失預警）

## MVP 驗收清單

- [ ] 併發下單 100 次同一時段，只成立 1 筆（防超賣）
- [ ] 預約成立與扣減同交易；失敗全回滾，帳本可重算餘額
- [ ] 取消後堂數正確返還並留 ledger 紀錄
- [ ] 班表改動後，可預約時段即時反映（快取失效）
- [ ] 跨商家資料完全隔離（越權測試通過）
- [ ] 時區：商家設定 Asia/Taipei，DB 存 UTC，前後端顯示一致

## 風險與對策

| 風險 | 對策 |
|---|---|
| 時段計算邏輯複雜（班表×例外×buffer×容量） | 時段引擎獨立模組 + 完整單元測試矩陣，先寫測試再實作 |
| 扣減對帳爭議 | append-only 帳本、任何調帳需備註、餘額可由帳本重算 |
| 政策組合爆炸（遲到×取消×改期） | 政策全部資料驅動（JSONB 規則），引擎統一判斷，不寫死在程式 |
| 通知送達率 | 多通道降級：LINE 失敗 → 簡訊 → Email |
