**節奏檢查**：每一格 2–3 秒內主體畫面就換掉，沒有任何一段靜止超過 3 秒。

## 三個刻意的決定

**一、手機畫面內只重現真實存在的元素。**
推薦卡片上沒有加「同系列」「相似材質」這類配對理由標籤——因為實際網站沒有。
推薦邏輯用字卡講。影片會被逐格看，演示到不存在的功能是最傷的。

**二、高亮框用品牌藍，不是黑色。**
它是後製標註，不是 app 介面的一部分。用產品自己的介面色會讓觀眾以為那是新的 UI。

**三、結尾收在購物車數字變化。**
功能影片要收在商業結果，不是收在介面。0 → 1 那一下才是這個功能存在的理由。

**四、片尾用現成的品牌資產，不重畫。**
CUBE 已經有一支 3.9 秒的正式片尾（空拍 + logo + 標語 + 夥伴 logo 帶）。
直接接上去，比重新做一個「很像」的可靠——`finish.sh` 就是做這件事。

## 素材檢查表

錄之前逐項確認，這幾項是重錄率最高的：

- [ ] 推薦出來的商品**真的合理**——這是整支影片的成敗點。配到不相干的品項就是反效果
- [ ] 預售倒數不會在錄影中途歸零
- [ ] 價格、幣別（MOP）、預售／現貨狀態正確
- [ ] 購物車數字從 0 開始
- [ ] 商品圖已載入完成再開始捲動（lazy-load 沒載完就捲過去很明顯）
- [ ] 關閉瀏覽器分頁列、網址列提示、通知
- [ ] 手機狀態列時間統一（截圖慣例用 9:41）

**真實網站錄製特別注意**：實際操作中，點推薦商品跳頁時會出現一段**整頁白底轉圈的載入畫面**。那一段要剪掉或蓋轉場，否則影片會停一拍。

## 兩種產出路線

**路線 A：用真實網站錄**（最有說服力，優先選這條）

```bash
node video/record.mjs --live https://koio.com/item/349671
```

Playwright 用 iPhone 尺寸開真實頁面、按分鏡捲動與點擊、輸出影片。同一支腳本每次跑出來一致，改版重錄成本幾乎為零。找不到推薦區塊時用 `--selector` 指定。

**路線 B：用 mockup 錄**（畫面不能外流、或功能還沒上線時用）

```bash
node video/record.mjs --mock
```

介面依實際版面重建：固定頁首、社群列、預售橘標、灰色倒數列、藍色加入購物車、紅色出貨日期框、標籤 chips、底部五格 tab bar、浮動查詢鈕。**唱片封面是抽象幾何佔位圖**，正式版請換成真實商品照。

兩條路的分鏡、字卡、節奏完全一樣。可以先用 B 給內部確認腳本，定案後再用 A 重錄交付。
